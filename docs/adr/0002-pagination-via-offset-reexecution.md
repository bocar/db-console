# 分页用 LIMIT/OFFSET 包装重执行，不跨请求持有游标

F-11 要求翻页复用原查询、数据源及事务上下文，并能读取超过单次返回上限的后续行。决定由后端对原查询加 LIMIT/OFFSET，每次翻页在同一事务连接上重新执行；无顶层分页或锁定子句时直接追加，避免 MySQL 派生表的重名列限制，已有这类子句时使用派生表包装。总行数用 COUNT 包装、能安全取得时才提供。包装后缀前换行，避免原查询的尾随行注释吞掉后缀。不跨 HTTP 请求持有打开的 ResultSet：持有游标会长期占用连接，超时、取消和连接池管理都复杂化。手动事务内快照一致，翻页无重漏。

## Consequences

- 无事务的普通查询翻页时可能看到数据变化（依赖隔离级别），可接受。
- 大偏移量翻页代价随偏移增长，由结果行数上限约束在可接受范围。
