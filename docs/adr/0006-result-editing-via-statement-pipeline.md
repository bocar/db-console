# 结果表格编辑复用语句执行管线，不建资源式行端点

F-17 结果表格编辑需要把网格中的增删改写回数据库，曾有两条路：资源式 REST 行端点（按表按主键 POST/PUT/DELETE 行），或由前端按方言生成 INSERT/UPDATE/DELETE 语句、走既有语句执行管线。裁决：**复用语句执行管线**。

理由：

1. **执行确认免费获得**。确认凭据绑定「会话 + 数据源 + SQL 文本」，生成语句天然落进这套绑定：DM8 等 PRODUCTION 数据源的写确认、无 WHERE 保护、凭据随文本变动失效、进程重启失效，全部无需新规则。
2. **资源端点必然平行复刻一套写路径**。确认签发、审计（逐语句、不含 SQL 与数据）、限流、并发登记、F-10 终态（执行结果未知不自动重试）都已长在语句管线上；行端点要在旁边重新实现一遍，两套规则迟早漂移。
3. **方言抽象现成**。语句生成复用 ADR-0001 手写分析器的操作分类与方言分派，首批 MySQL + DM8 与 F-13 双库验收基线对齐。

## Consequences

- 保存批次是语句管线里的**新执行形态**：独立连接上的单一显式短事务（按删除、更新、新增顺序，整体提交或回滚），区别于既有的单语句自动提交与手动事务——与手动事务互斥，不占用其连接。
- 确认凭据绑定「语句 + 参数规范渲染」：参数化语句只约束形状，值变即绑定文本变、凭据失效（比单语句的纯文本绑定更严，为参数化所必需）。保存批次**一律先经一次汇总确认**——即使全部语句都无 F-09 风险（如开发环境带主键谓词的写），确认仍是保存的必经步骤，凭据逐条签发、全部通过才执行（特性级裁决 2026-11-18）。
- 审计按批次记一条汇总（段计数指纹，不含 SQL 与数据）：批次是原子提交单元，整体回滚时逐语句状态会误导（裁决 2026-11-18）。
- 若将来出现真正的结构化同步需求（如离线 diff 回放），资源式端点可再评估；本决策不预承诺。
